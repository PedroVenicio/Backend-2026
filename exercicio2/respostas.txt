Exercício 1.1
Pergunta: Por que "new Conta("Fulano", "0000-0")" para de compilar e "new ContaCorrente(...)"  funcionando?

Resposta: porque ao tentar criar um objeto (instanciar) de "Conta", o java não permite pois conta agora é abstrata, sendo apenas "um conceito", permitindo que subclasses herdem parâmetros e métodos, mas nunca que crie um objeto diretamente a partir dela.

Exercício 2.1
Pergunta: O método transferir() tem três linhas e não sabe que a corrente cobra taxa nem que a estrangeira converte moeda. Como as duas regras foram aplicadas então? Qual conceito de POO está agindo aí?

Resposta: O conceito de OOP é o polimorfismo. Basicamente, ao chamar o método transferir com um objeto instanciado da conta corrente ou estrangeira, o Java sabe se há um método sobrescrevendo o transferir do pai, dessa forma utilizando o método do filho. Caso não tenha nada sobrescrevendo, é utilizado o método do pai.

Exercício 3.1
Pergunta: Qual a diferença entre classe abstrata e método abstrato? O exemplo tem os dois agora: aponte cada um.

Resposta: Uma classe abstrata é uma classe que não pode ser instanciada, enquanto um método abstrato é um método declarado na classe pai (abstrata) e que não é preenchido. Dessa forma, as subclasses herdam o método, mas como ele não tem nada escrito, da erro para que seja obrigatório implementar esse método especificamente pra cada classe

Exercício 3.2
Pergunta: O que acontece se uma subclasse não implementar tipoDeConta()? Teste, leia o erro e copie a mensagem do compilador na resposta.

Resposta: o erro é "contas.ContaCorrente is not abstract and does not override abstract method tipoDeConta() in contas.Conta", ou seja, a conta corrente não sendo abstrata, precisa implementar o método abstrato, pois ela irá gerar objetos a partir dela.

Exercício 3.4
Pergunta: Conta agora tem um método com corpo (sacar) e um sem corpo (tipoDeConta). Uma interface poderia ter os dois? Por que a Conta não é uma interface?

Resposta: a interface não poderia ter os dois, pois o método "sacar" possui um comportamento padrão que todas as contas vão seguir, a não ser que o método seja sobrescrito. Se conta fosse uma interface, seria necessário escrever "sacar" em cada nova subclasse
